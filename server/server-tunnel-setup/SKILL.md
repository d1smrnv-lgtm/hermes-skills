# Server Tunnel Setup

- Отвечайте кратко по-русски: файл, проверенный результат, оставшиеся действия.
- Сначала проверьте по SSH ОС, интерфейсы, `wg show`, `awg show`, службы, маршруты, sysctl и `iptables-save`. Не полагайтесь на старые заметки.
- **Дисквери параметров:** никогда не угадывайте порт, адрес или интерфейс. Порт узнайте из `cat wg0.conf`/`awg0.conf` или `ss -ulnp | grep wg`. Внешний интерфейс — из `ip route | grep default | awk '{print $5}'`. IPv4 сервера — из `ip -j a | python3 -c "import sys,json; [print(i['addr_info'][0]['local']+' -> '+i['ifname']) for i in json.loads(sys.stdin.read())]"`. Адрес подсети — из текущего конфига, не по шаблону.
- Для AmneziaWG используйте модуль `amneziawg`, `awg` и `awg-quick`; не выдавайте обычный WireGuard за туннель с обфускацией.
- Проверяйте наличие инструментов и модуля до установки; пакет и модуль могут отсутствовать в стандартном репозитории. Не обещайте, что `apt install amneziawg-tools` всегда сработает.
- **AmneziaWG игнорирует `/etc/wireguard/awg0.conf` при рестарте через systemd.** Установщик пишет параметры в память и перестраивает конфиг каждый раз; `wg-quick` копирует файл из `/etc/wireguard/`, а `awg-quick` — нет. При конфликтах или нестабильности перезагрузите peer напрямую через `awg set` и проверяйте `awg show <iface> dump` для live-параметров вместо чтения файла. Если AmneziaWG «съедает» ваши настройки после каждого `systemctl restart`, переключитесь на стандартный `wireguard-tools` (`wg` + `wg-quick`).
- Генерируйте новые ключи `awg genkey`, `awg pubkey`, `awg genpsk`, не храните приватные ключи в навыке, выводе или памяти. Конфиги — chmod 600.
- Делайте root-only резервную копию перед изменениями. Удаляйте существующие туннели и peers только по явному разрешению пользователя. Не сбрасывайте весь firewall.
- Клиенту задайте DNS, MTU, Endpoint, PersistentKeepalive=25 и AllowedIPs=0.0.0.0/0, ::/0. Параметры Jc/Jmin/Jmax/S1/S2/H1–H4 должны совпадать на сервере и клиенте.
- Для одного клиента задайте серверный AllowedIPs как его IPv4 /32. Включите IPv4 forwarding и NAT на внешний интерфейс, добавьте прямое и established/related FORWARD-правило. Правила добавляйте идемпотентно через PostUp, службу включайте systemctl enable.
- Если IPv6 отключён на сервере, не назначайте IPv6 адрес и маршрут в серверном awg-quick: служба падает. Клиентский ::/0 захватывает IPv6 и предотвращает прямой обход, но не предоставляет IPv6-интернет. Явно сообщайте это ограничение.
- Проверяйте точный записанный конфиг, active/enabled, один ожидаемый peer и правила после изменений.
- Перед генерацией клиентского конфига и QR точно определи мобильное приложение: AmneziaWG (иконка A) принимает только AWG-диалект (Jc/Jmin/Jmax/S1/S2/H1–H4 обязательны), стандартное приложение WireGuard принимает только чистый диалект без этих параметров. Ошибка клиента «unknown section in config» почти всегда означает несовпадение диалекта с приложением, а не битый файл — не перегенерируй тот же диалект в надежде, что пройдёт. См. references/amneziawg-pitfalls.md.
- QR для клиента кодирует НЕ сырой конфиг: payload = `config=` + URL-encoded полный текст .conf (`python3 -c "import urllib.parse; print('config='+urllib.parse.quote(open(conf).read().strip(), safe=''))"`). `qrencode -r file.conf` даёт сырой текст — приложение его не примет. Пиксельный размер и поля важны: `/usr/bin/qrencode -o qr.png -s 8 -m 4 "$(cat payload.txt)"` (маленький `-s` без `-m` даёт битый по quiet zone код).
- Проверяйте реальный handshake и интернет через изолированный network namespace: veth до хоста, отдельный маршрут endpoint, amneziawg-интерфейс с клиентскими ключами, default через туннель; ping сервера и HTTPS-проверка внешнего IP. Удаляйте namespace и временный конфиг в finally. Этот тест подтверждает серверную часть, а не доступность UDP из клиентской сети.
- Не запускайте тестовый клиент с тем же ключом одновременно с реальным: endpoint peer перемещается. После теста переподключите приложение клиента.
- Если handshake есть, но данные не ходят, смотрите счётчики, tcpdump внешнего и туннельного интерфейса, NAT, FORWARD, MTU, DNS и маршруты клиента. Проверяйте `netstat -rn`, `route -n get ENDPOINT`, `scutil --dns` на Mac: другой VPN может захватить endpoint и default. Не утверждайте, что статус Connected доказывает исправность интернета.
- Не заявляйте об успешном клиентском подключении без проверки именно на клиенте. Если другой VPN обеспечивает текущий доступ, не отключайте его без согласования; попросите включить только AmneziaWG для финальной проверки.
- **AmneziaWG бинарник ≠ awk:** команда `awg` может быть принята оболочкой за встроенный `awk`. Используйте полный путь `/usr/bin/awg show <iface> dump` и проверяйте `which awg`. Ошибка вида `awk: fatal: cannot open file 'awg0'` — это не проблема конфига, это выполнена другая команда. См. references/amneziawg-pitfalls.md.
- **Service-switching protocol при переключении WireGuard ↔ AmneziaWG:** остановить обе службы (`wg-quick@wg0` и `awg-quick@awg0`), удалить старый интерфейс вручную (`ip link del <old>`), подождать 2 сек cleanup, затем создавать новый. Иначе служба падает с «device already exists».
